# Landmark jitter: how stable is the picked meme when hand landmarks wobble?

## Question
`choose-dynamics` covered dropped frames; `hand-invariance` covered rotation, aspect and malformed arrays. Neither covered
small per-frame landmark noise, which every live MediaPipe stream has. `fingerState` uses hard ratio tests
(`ext`: tip-to-wrist > 1.12 x pip-to-wrist; thumb 1.1 and 0.55). A half-curled finger sits near those cut-offs. How often
does noise flip the meme the user sees, and for which gestures?

## Method
- `lab/jitter/sim.mjs <test-dir> [perClass=300] [draws=20]`. Data: HaGRIDv2 test landmarks from `lab/hagrid-annotations`.
- For the first 300 landmarked images per class (34 classes, 10,200 images), take the noise-free pick (all `MEMES`,
  neutral face, 0.35 floor, as in `meme-confusion`). Then add i.i.d. Gaussian noise to every x,y of every landmark. Sigma
  is 1, 2, 4 or 8 % of hand size (|wrist - middle MCP|). Do 20 draws and re-pick each time. Seeded LCG, so deterministic.
- Metrics: mean agreement with the noise-free pick, and the share of images where agreement is under 90 %. The second
  one is the images that would visibly flicker.
- Caveats: HaGRID landmarks already come from MediaPipe, so they carry some noise of their own, and the added noise
  stacks on top. I did not measure real frame-to-frame sigma on a phone. 1-2 % is my assumption for a steady hand,
  4-8 % for a moving or small (far) hand. No EMA or dwell is applied, so this is the raw per-frame decision (the app
  smooths; see `choose-dynamics`). Raw output: `lab/jitter/output.txt`.

## Results (agreement % at sigma 1 / 2 / 4 / 8 % ; then images <90 % agreement at 2 % and 4 %)
| class (app meaning) | agreement | unstable images |
|---|---|---|
| one (point) | 99.9 / 99.8 / 99.8 / 99.0 | 0.7 % / 0.7 % |
| fist | 99.2 / 98.9 / 97.2 / 94.4 | 2.7 % / 7.7 % |
| like (thumbs) | 97.2 / 94.0 / 86.0 / 71.0 | 19.0 % / 36.3 % |
| call (shaka) | 96.9 / 93.6 / 86.6 / 75.2 | 17.7 % / 35.3 % |
| palm (open palm) | 97.8 / 95.3 / 91.3 / 76.6 | 12.7 % / 21.0 % |
| stop (open palm) | 97.0 / 94.3 / 89.1 / 79.1 | 14.7 % / 30.0 % |
| hand_heart, grip, grabbing (two-hand look-alikes) | 92-93 / 84-89 / 72-80 / 58-70 | 35-39 % / 57-63 % |
| all 34 classes | 97.9 / 95.9 / 92.1 / 85.6 | 11.3 % / 20.1 % |

- Pointing and fist are robust, with a big margin. This is the same "easy" group as in the recall results.
- The gestures that depend on the thumb (thumbs-up, shaka, open palm) are the fragile ones. The thumb test is the
  tightest ratio, and the thumb-up test also needs `h[4].y < h[2].y - 0.35 size`. At just 2 % jitter, about 1 in 5
  thumbs-up or shaka hands is unstable (under 90 % agreement over draws), and at 4 % it is over a third.
- Noise also hurts the cases that currently produce no meme: `no_gesture` and `timeout` are 93 % stable at 2 %.
  Spurious memes appear and disappear.

## What the planner should do next
1. A hysteresis or per-finger smoothing of the finger flags is the cheapest fix. Option: smooth `d(tip,wrist)/d(pip,wrist)`
   with the same EMA as the scores, or use two thresholds (enter 1.15, leave 1.05). This should be a test: noise sigma
   2 % on the synthetic hands in `test/memes.test.js` must keep thumbsUp/shaka/openPalm above 98 % agreement.
2. Any threshold change from `threshold-sweep` (looser thumb test for palm/shaka) moves the cut-off nearer or further
   from the typical hand, so rerun this sim as a second gate next to the recall numbers. The harness is generic.
3. Phone measurement is missing. M2's smoke clip could log raw landmark std-dev per frame on a held hand, which would
   say which sigma row applies.
